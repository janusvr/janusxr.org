JanusXR re-imagines webpages as collaborative 3D webspaces interconnected by portals. It straddles the line between a web framework like React or Angular and a game engine like Unity or Roblox — which means it's at home building multiplayer worlds, data visualizations, simulations, games, industrial control systems, and very fancy websites. Standing around in a website with your friends is just the floor — your imagination is what defines the ceiling.

One engine, three ways in

Build in-world

Walk in and start placing blocks. The collaborative in-world editor lets you and your friends build together in real time — no code, no tools to install, no leaving the browser.

Editor guide →

Write markup

A whole world in a text file. Janus Markup Language (JML) describes rooms the way HTML describes pages — declarative, view-source-able, hostable anywhere you can host a file.

JML reference →

Script everything

Custom entities with event-driven logic, driven by JavaScript. Build full applications: live dashboards, simulations, games — anything the web can reach, your world can render.

Scripting API →

Completely decentralized

Worlds are hosted like websites: anywhere, by anyone. Portals connect them the way links connect pages. There's no central server to shut down, no platform to deplatform you, no land to buy. Host your content on the open web and run your own multiplayer server if you like — or use ours.

> How can I get JanusXR?

The web client

You mostly already have it. JanusWeb runs in any modern browser — launch it and you're in. Desktop, mobile, and WebXR headsets all welcome; versioned engine builds are hosted at web.janusxr.org if you want to pin one.

Host it yourself

Everything is self-hostable: embed the JanusWeb client in your own site, serve your own worlds from any static host, and run the multiplayer server to give them presence. Your worlds live on your infrastructure, under your rules.

The vault: legacy & alternative clients

From 2014 to 2019 Janus was a native desktop application. It's no longer maintained, but we keep it on a shelf behind glass — for history, for curiosity, and for the handful of things it still does best.

  • Archived native client builds — the JanusVR desktop client, preserved.
  • Alternative & community clients — implementations by the community, past and present.

Deploy it however you like

Embed a world inside an existing website. Ship a full-page game or app. Point a translator at an existing 2D website or API and walk around inside it. Wire it into a dashboard, a kiosk, an art installation — there are many ways to deploy, and most of them haven't been invented yet.

Built in the open — come build it with us

JanusXR is a community project. Not "open core," not "source available" — open, the way the web used to make things. Every part of the stack is on GitHub, every part could use another pair of hands, and every level of involvement counts:

  • Hang out — explore, meet people, and tell us what's broken.
  • Build worlds — every good world is an advertisement for all the others.
  • Write docs — the expanded documentation project is underway and needs writers.
  • Make themes — this site's own 3D space is reskinnable, and the theme format is a contribution on-ramp.
  • Hack the engine — client, server, tooling: it's all there.

The repositories

  • janusweb — the in-browser client. Start here.
  • janus-server — the multiplayer presence server.
  • elation-engine — the engine underneath, in development since 2010.
  • janus-custom-components — a collection of custom elements to drop into your worlds.
  • janus-script-ui — programmable scripting objects for interactivity.

    > When are we?

    Janus is the middle of this story, not the end of it. Virtual worlds have been swinging between corporate platforms and open standards for half a century — this is our stop on a much longer line.

    ◂ The tube to the past

    The line goes back further than you think. A few stops, with more being excavated:

    1. 1978 open MUD — text-only shared worlds, built at a university and given away. The pattern starts here: a world is just a server anyone can run.
    2. 1986 corporate Habitat — Lucasfilm puts avatars on a Commodore 64. Brilliant, beloved, and owned.
    3. 1990s corporate SGI — the graphics workstations that made real-time 3D real, at workstation prices.
    4. 1995 open VRML — the open 3D web standard, born when SGI's tech met Netscape's browser. Ahead of its time; the time is now catching up.
    5. 1995 corporate ActiveWorlds — persistent user-built worlds at dial-up speeds, on a company's servers.
    6. 2000s corporate Second Life — a virtual economy at scale, and a lesson in what it means when the platform owns the world.

    ◉ This station: Janus, 2010 – present

    1. 2010 Elation Engine — development begins on the JavaScript engine and web framework that still powers everything below.
    2. 2014 FireBox — James McCrae's experiment: what if webpages were rooms, and links were portals you walked through?
    3. 2015 JanusVR, Inc. — the company era: a native client, funded development, and lobbies full of people.
    4. 2016 JanusWeb — the engine comes to the browser. No install; a world becomes something you can link to.
    5. 2019 JanusXR.org — the company winds down and the project goes fully open. Born from the ashes; community-run ever since. You are here.

    The tube to the future ▸

    Well-lit, under construction, and hiring. Some of what's on the line ahead:

    • soon The open web catches up — WebXR on every headset, WebGPU rendering, browsers that treat 3D as a first-class citizen.
    • next An open metaverse — portable avatars and identity, interoperable worlds, and the standards work to make "decentralized" stick this time.
    • someday The stuff from the books — the Street, the matrix, the holodeck. Somebody has to actually build it. It won't be a corporation.
    • now Your part — this tunnel is unfinished on purpose. Grab a hard hat.
